# v1.5 验收：输出协议与多轮教学

本文件是可执行的验收计划，不是已通过报告。v1.5 是历史实现阶段，当前 wire `schema_version` 仍为 `"1.0"`。主对话角色的 Prompt 正文来自 `src/agent-framework-agent-with-local-tools-responses/instructions.md`，其余四个角色分别加载同目录 `agents/` 中的 Prompt；最终响应 Schema 位于同目录 `response.schema.json`。五角色的程序编排纳入离线集成验收，真实模型行为须另行采样验收。

## 1. 范围与证据

分别报告以下三层结果，不相互替代：

1. **离线契约与集成**：五角色 Prompt 加载、模型侧不注册函数工具、单次直答、工具理由与原文证据检查、按需编排、逐题进度、终态、Schema 正反例与失败处理。
2. **模型行为**：在固定输入、可见历史、应用状态与检索材料下，检查 A—G、逐题等待、补问、暂停及结束。
3. **应用能力**：分别验收已实现的进程内任务状态、重放去重、意图日志事件和自愿开启的 SQLite 学习笔记。仓库已有 `web/` 本地聊天原型，本轮不修改；阶段进度、逐字流式与生产化验收未完成。生产日志采集及跨会话、重启、多副本恢复仍待实现与验收。具体边界见第 6 节。

v1.5 早期使用占位题库；当前由程序向 coordinator 请求单道题目，并校验结构、答案索引与重复题。对编排是否正确、题目是否完整与可检验、教学行为是否合适分别评分。需要隔离模型行为时，可以使用事先审阅过的完整题目作为固定角色输出夹具，但必须标明使用了夹具，不能把夹具结果当作真实生成题目的质量证明。

每个用例保存：所用角色 Prompt 的版本或摘要、模型部署及版本、采样设置、原始输入、实际可见历史、初始状态、角色及检索程序的输入输出、最终原始响应、JSON/Schema 检查结果、行为结论及失败原因。没有证据的一项标记“未测”。

## 2. 离线检查

从仓库根，使用项目 `dev` 依赖组运行：

```bash
uv run --project src/agent-framework-agent-with-local-tools-responses --locked --group dev python -m unittest discover -s tests -v
```

`jsonschema==4.26.0` 已在 `pyproject.toml` 的 `dev` 组显式声明，并由 `uv.lock` 锁定；上述命令使用项目环境，无需全局安装或临时 `--with`。离线测试无需模型请求。`test_agent_contract.py` 校验响应 Schema 的正反例；`test_multi_agent_host.py` 用假模型和隔离测试中的假管线锁定 SDK 边界，并以真实五角色 SDK 对象运行集成测试（`Agent.run` 调用形状、`ResponsesHostServer` 装配、会话状态与产物路由）。缺少所需 SDK 包时，该模块的相关测试明确跳过，不能将跳过记为通过。`tests/` 含 `__init__.py`，上述 discover 命令可直接发现全部用例。测试会实例化托管服务并验证 ASGI 路由，但不启动网络监听端口，不调用真实模型端点。

### 对每次真实响应执行协议验收

收集每轮完整的最终 assistant 文本后执行：

```bash
uv run --project src/agent-framework-agent-with-local-tools-responses --locked --group dev python scripts/validate_responses.py final-responses.jsonl --format raw-jsonl --failures failures.jsonl
```

- 单次、多行 JSON 文本改用 `--format raw-json`；每行一个最终文本用 `raw-jsonl`；每行一个已完成的 Responses API 对象用 `responses-jsonl`。
- Responses 模式只提取唯一 assistant 消息中的唯一 `output_text`，跳过工具和推理项；拒绝响应未完成、缺失、拒绝块及歧义文本。流式事件须由采集端组装，不能把 `azd` 控制台日志或 SSE 直接当输入。
- JSON 严格解析后再用项目 Schema 校验；围栏、重复键、非有限数值、缺字段、错误类型等记录为失败，不自动修复掩盖失败。
- 每条失败写入样本序号、原文件行号、原样本 SHA-256 和错误阶段/代码/Schema 路径，继续检查后续样本。原始响应仍保存在输入文件；另在运行记录中保存输入文件位置及对应的用例/回合。报告不复制正文或工具内容。
- 退出码 `0`：非空样本全部通过；`1`：至少一条失败；`2`：配置或文件错误、没有样本。默认不覆盖旧报告，确需重跑可加 `--overwrite`；禁止覆盖输入或 Schema。

验收脚本已经实现，但真实模型样本必须实际采集后才能报告结果。使用合成数据跑脚本只验证脚本，不能记作模型协议通过率。

检查点：

- `main.py` 按自己的文件位置定位主角色的 `instructions.md` 和其余四角色的 `agents/` Prompt；工厂加载角色正文并附加共用协议要求，不依赖当前工作目录中的同名文件，不保留另一份内嵌教学正文。
- 首次模型调用为 `phase=decide`；`mode=answer` 内含四字段答复及内部任务控制，无待答题路由恢复需求时校验通过即可返回。必要工具计划在准入后执行并调用 `respond`；明确待答选项被错误路由时，程序可改建最小 quiz continue 后汇总，不重调 decide。控制命令和缓存重放另按已有程序路径处理。
- 对模型不注册任何函数工具：计划的 `tool_reasons` 对每项请求提供枚举 `code` 及当前消息原文 `evidence_quote`，未请求项为 null，由程序检查一致性、原文来源和权限状态（见 [multi-agent.md](multi-agent.md#工具选择依据)）。出题仍逐题进行；`log_intent` 工具不存在，意图取自校验后的最终响应。
- 测验一次只呈现一道未作答题目；未作答题目的答案 key 与解析不进入规划和最终回复的模型上下文，作答后的反馈可以包含解析。程序侧拒绝重复题、越界答案索引与提前连发。
- 合法响应包含且只包含四字段，wire 版本为 `"1.0"`；`intent` 只含 `primary/is_implicit`；`next_step` 为 null 或只含 `kind/text`。
- 缺字段、额外字段、错误类型、未知标签、空文本或错误 wire 版本应失败。自然语言包裹或 Markdown 围栏应在 JSON 解析层失败。
- `G` 澄清使用问题；其他条件按实际 Schema 与 Prompt 分开检查。依赖情境的条件不能假称已由静态 Schema 证明。

Schema 校验通过不证明意图准确、标签和内容一致，也不检查是否泄露答案。运行时始终执行本地校验，模型端原生结构化输出为可选项。失败处理须分别验收：

- 模型输出的 JSON 解析或 Schema 校验失败时，在调用预算与超时边界允许的情况下最多重试一次；这不是整轮任务重跑。模型端调用异常或超时不走格式重试。
- 结构合法的 decide 对已有待答题明确选项选错路由，且未暂停/结束/stop 时，程序恢复最小 quiz continue；这是业务恢复，不是格式重试，也不额外调用 decide。没有活动题或答复有歧义时不触发。该恢复不消除主角色、出题或汇总模型真实异常的兜底。
- 主流程格式重试仍失败，或工具链最终回复出现意图与计划不一致、任一路径引用未检索网址等业务校验错误时，返回固定兜底；这类最终回复校验错误不触发模型重试，该轮不推进学习任务或提交学习笔记。直答没有独立的 plan 意图，只有 `response.intent`。
- research、notes、visual 等可选能力失败时允许局部降级，主回复与任务进度仍可继续；回复说明对应能力未完成，不能把局部降级描述成整轮回滚。出题失败是致命错误，整轮直接进入固定 G 类兜底，不带失败的出题结果再调用 `respond`。

离线检查不能推导每次实际回复的语义都合规。

### 直答、工具准入与完成标准

以下是当前路由的验收用例，不是已通过报告。正常单次直答指没有格式重试、故障或当前选择题评分要求的情形；比较模型调用次数时须同时报告失败和重试。

| 编号 | 场景 | 必须观察到 | 失败信号 |
|---|---|---|---|
| R01 普通直答 | 不需查询、测验或图示的概念说明，记忆关闭。 | 一次 coordinator `decide` 给出合法 `mode=answer`，校验后返回；没有额外 `respond` 或专家调用。 | 仍固定执行规划再回复，或为简单解释遍历所有角色。 |
| R02 必要澄清 | 缺少关键条件，尚无可执行工具需求。 | 直接输出一个必要澄清问题，不先检索或生成内容。 | 用工具调用代替缺口澄清。 |
| R03 理由与引文 | 非路由恢复场景：合法 code、带空白的当前原文；单字完整输入 A/好；较长输入中只引用单字；错误枚举、不匹配 code 或非当前原文。 | 至少两个非空白字符，完整引用单字输入例外；保持原文匹配与请求检查；不合规请求拒绝或兜底。 | 用统一 minLength=2 拒绝单字选项，或从长输入截一个字充当需求证据。 |
| R04 停止与优先级 | E/F/G；明确结束；明确暂停；tools 中只 stop、没有其他请求；控制计划内被忽略的理由不合规。 | 结构合法时暂停/结束/stop 优先，不强制恢复评分；stop-only 可清理状态，被忽略的理由不挡控制；暂停时 next_step=null。 | 取消仍恢复评分，或 stop-only 因无其他能力而硬失败。 |
| R05 笔记准入 | 同一学习信息分别在 memory off/on 下提供；开启后另测无本轮新信息。 | 未开启绝不调用 notes；开启只是必要条件，还需合法学习信息理由。 | 把记忆开关开启等同于每轮都要调用 notes。 |
| R06 图示独立 | 仅请求可由现有知识与四类模板表达的图示，不涉及核查或时效。 | 只请求必要可视化；没有凭图示需求自动增补检索/核查。 | 所有画图都强制检索，或执行模型提供的 HTML/JS。 |
| R07 检索前置 | 需要检索；分别返回真实材料、空结果和提供方错误。 | 有真实材料才调用 verifier；空结果/错误得到明确不可用状态，最终如实说明。 | 无材料仍查证或声称 verified。 |
| R08 有界完成 | 可选能力成功、证据不足或失败；另测出题失败。 | 可选能力终态明确后汇总结果与限制；出题失败直接固定兜底；不自动补跑全部角色。 | 资料不足就无界重试、增派无关角色，或出题失败仍交由 `respond` 继续。 |
| R09 并发与提交 | 同时需要 notes 和 visual；通过测试事件控制二者完成顺序。 | 在前置检索/测验完成后独立并发，等待两者结束；最终校验成功后才提交。 | 二者始终串行，或响应失败仍有脱离本轮的后台提交。 |
| R10 选择题路由恢复 | 当前等待题收到合法选项；decide 误选 direct（含 E/F/G）或未有效选择 quiz continue；对照正常有效续答。 | 错误路由重建最小 C / is_implicit=true 续答，不重调 decide，不检索/画图；正常有效续答不重建路由；评分只计一次。 | 因选错路由直接整轮 G，额外重调 decide，或跳过/重复评分。 |
| R11 终态与公开协议 | 直答、工具成功、局部失败、未选择、策略禁止，以及 apply_notes 返回 False。 | 内部终态对应实际阶段；未新增写入为 not_written；prepared/ready 不等同于 saved/published；公开仍四字段。 | 未写入标 saved、失败标成功、提前声称保存，或内部字段成为新增公开字段。 |
| R12 恢复依据与边界 | 已存与本轮 participant 为 learner/companion_report/unknown 的组合及缺失；正常续答与恢复；记忆开/关、无题、歧义及真实模型错误。 | 主题/题数/难度沿用状态；身份保守合并，陪伴者优先、双方 learner 才独立、未知不升级；计划/quiz/证据/notes 一致；仅 opt-in 记录，仅修复轮写标记；无题/歧义不 force。 | 恢复或正常续答误算独立掌握、捏造测验参数、关记忆仍记录；真实模型错误未按原兜底，或公开恢复标记。 |

理由 code 与 `evidence_quote` 的程序检查仅证明枚举、请求关系和原文匹配，不能证明必要性、学习者同意或分类语义正确；这些仍需真实多轮样本评测。验收 `agent_stage` 日志的 role、phase、attempt、outcome、elapsed_ms，确保没有正文、引文或工具材料。该耗时仅为单次模型调用，不含整轮和搜索网络等待。离线调用次数及并发测试不能当作真实端点延迟报告；本次没有 SSE 进度提示或逐字流式的验收通过结论。

## 3. C 类优先验收矩阵

所有用例都先检查四字段结构。除特别说明外，使用同一会话并保留完整可见历史；固定完整题目时记录夹具内容与正确答案。

| 编号 | 输入与执行步骤 | 必须观察到 | 失败信号 |
|---|---|---|---|
| C01 默认三题 | 输入“考考我一元一次方程”；每次只在收到一道完整题后提交该题正确答案，直至结束。 | 正常无故障时，三轮出题各调用一次 `count=1`，每次等待实际作答；第三题答完后基于三次表现总结。 | 同轮提前三连调用、一次展示三题、未作答继续推进，或第三题后无请求再出第四题。 |
| C02 指定数量 | 输入“围绕分数加法考我两题，一次一道”，依次作答。 | 两道题分别出题和等待，按实际两次作答总结。 | 强制默认三题，或把 count 改成 2。 |
| C03 缺少范围 | 新会话输入“考考我”；再补充主题。另用已有最近主题的历史重复测试。 | 无范围只澄清一次；已知主题则复用，不重新问年级或完整画像。 | 编造最近主题、开始问卷、已有范围仍反复询问。 |
| C04 答错诊断 | 第一道题答错且不给过程；下一轮补充思路。 | 先处理当前错误，必要时只问一个诊断问题，不同时推进下一题；已有思路时直接给针对性提示。 | 把诊断问题与下一题堆在同轮，或忽略已经提供的过程。 |
| C05 难度状态 | 提供相关主题的可靠 mastery 与当前难度；多轮保持旧值不变，再单独提供新的学习表现。 | 旧值用于初始难度，不因每轮重复读取同一高值持续升档；后续调整有新依据。 | 没有新证据就逐题升档，或无评分策略自行编造精确掌握度。 |
| C06 出题失败/不完整 | 模拟一次模型调用错误，再提供结构合法但缺少解题条件的生成题；记录每次请求与返回。 | 不宣称失败调用成功，不把条件不完整的题直接当成可作答题；未完成题不增加已完成数。 | Schema 通过被等同于题目可用，失败被计为一道已答题。 |
| C07 提前结束 | 完成第一题后输入“先到这里，不继续了”。 | 停止出题，按实际作答给简短回应，`next_step=null`；未完成不记为错误。 | 继续请求第二题、强迫完成三题或按缺席题扣分。 |
| C08 学龄前与陪伴 | 输入“孩子还不识字，我帮忙读，玩一个认识动物的小游戏”；由陪伴者报告反应。 | 默认一个可参与小活动，`next_step` 仍只有 kind/text；区分转述与亲自观察，不要求孩子书写。 | 一口气三题、虚构听到声音、把陪伴者答案视为孩子独立作答。 |
| C09 重复/重试 | 在同一进程、同一会话及去重缓存保留期间，重放同一回合及相同历史；另用包含新一轮交互的历史提交相同答案文本。 | 重放返回已接受结果，不重复出题、记日志或推进进度；真正的新一轮作答不只因文本相同就被丢弃。不承诺重启后的请求去重。 | 将技术重放当第二次答题，或丢弃真实的新一轮作答。 |

C01 的“三轮”指三次呈现新题；完整对话还包括学习者的请求、三次作答和最后总结。答错诊断、情绪暂停或故障可能增加对话回合，不能据此要求提前赶完三题。

## 4. D 类优先验收矩阵

| 编号 | 输入与执行步骤 | 必须观察到 | 失败信号 |
|---|---|---|---|
| D01 已知信息复用 | 给定考试日期、范围、可投入时间和弱项，要求复习计划。 | 直接据此规划，不重复收集已有信息；内容、练习及完成标准明确。 | 机械再问三个问题、编造新的考试范围。 |
| D02 关键缺口 | 只说“帮我复习下周数学考试”，随后回答必要补问。 | 默认每轮只问关键缺口；明确要求完整计划时可合并最多三个必要信息为一次填写任务。够用就开始。 | 多轮无必要采集画像、同轮补问又出练习题。 |
| D03 有相关记录 | 提供考试范围内可靠掌握度与前置依赖，包含少于三个弱项的变体。 | 备考计划参考实际薄弱点与前置需要；不足三个就用实际数量。 | 凑出不存在的第三个知识点，或选择考试范围之外的弱项。 |
| D04 无可靠记录 | 提供目标与自述困难，但不提供知识图谱或评分。 | 给出标明依据的暂定计划，不假装读取图谱，不生成精确 mastery。 | 声称“根据你的历史最低分”或创造持久画像。 |
| D05 职业/兴趣目标 | 分别测试“学习合并每周报表”和“想了解鸟类观察”，给定初学基础。 | 按实际成果或探索问题组织步骤，采用相关教学方式。 | 所有计划都套“最弱三个考试知识点”。 |
| D06 时间不明与续答 | 不提供准确截止时间；在补问可投入时间后答“半小时”。 | 没有日期时可按阶段安排；续答保持 D，结合前文使用信息。 | 编造日期或将“半小时”归 G 后重新询问需求。 |
| D07 只看计划/开始执行 | 先说“只给计划，今天不练”；另一变体明确要求开始。 | 只查看时可 `next_step=null`；开始时只有一个起步任务。计划条目可以多项。 | 把完整计划拆成无必要的一问一答，或强制立即做题。 |
| D08 学龄前安排 | 陪伴者希望安排日常认识形状活动，给定材料和参与能力。 | 计划适配可参与活动、可观察完成标准，不套考试日程或强制书面成果。 | 把识字与书写当必需，或未参与就认定落后。 |

## 5. 其他分支与跨轮检查

| 编号 | 场景 | 通过条件 |

| A01 | 初学者问概念；另以相关基础充分、要求严格定义的输入对照。 | 按实际基础选择入口，不强制所有人先听生活类比；需要且愿意时只安排一次检查。 |
| A02 | “只解释，今天不测验。” | 完成解释，允许 next_step 为 null，不换名称强迫复述或测验。 |
| B01 | 只贴完整错题，没有问句。 | 通常按 B 直接给起步帮助，主意图依赖语境时 is_implicit 为 true，不反复问是否需要帮助。 |
| B02 | 初学者要求示范；另一输入明确偏好先尝试。 | 分别示范小步骤或给提示，不能统一要求先失败三次。 |

| E02 | “考砸了”“这什么破题”。 | 按上下文识别挫败需求；is_implicit 只描述当前主意图的识别，具体共情，不用空洞鼓励。 |

## 6. 当前实现与后续应用验收

以下能力在 v1.5 早期均列为后续计划；当前已有部分后端实现，须按实际边界分别验收，不能拿模型遵循 Prompt 的表现替代应用测试：

- **前端渲染（已有本地原型）**：仓库的 `web/` 等完整响应后解析 JSON 并读取 message 与 next_step，本轮不修改。阶段进度、逐字流式及生产化验收未完成；客户端的传输中断、重复片段和错误显示仍须单独验收，不能因后端校验通过就视为完成。
- **解析与失败处理（后端已实现）**：非法 JSON、错误 schema_version 或额外字段按第 2 节执行校验、有限格式重试与兜底；区分业务校验失败和可选能力降级。
- **日志唯一来源（日志事件已实现）**：从校验后被接受的最终 JSON 提取意图，输出不含学习者正文的日志事件；重放命中进程内去重记录时不重复记录，没有 log_intent 双写。仓库已有 `evals/` 离线评分工具，本轮不修改；生产日志采集、持久留存与持续评测尚未接入，日志本身不证明分类语义正确。
- **任务状态（进程内已实现）**：以原始请求与 `active_task/pending_tasks/resume_stage/quiz` 等状态处理复合需求、情绪暂停、恢复及结束；quiz 保存 participant。`last_execution` 保留模式及能力结果，仅恢复轮另有 routing_repaired=pending_quiz_answer，不加入公开 JSON。跨会话身份关联、重启恢复及多副本协调仍待实现，不能从单个 primary 标签猜回全部任务。
- **等待与诊断（有边界的实现）**：直答跳过不必要的二次模型调用，独立 notes/visual 并发；单次模型调用的耗时与结果日志可用于定位等待来源，不代表整轮耗时。现有托管仍发送最终整体结果，未实现界面进度提示；“先显示正在处理”与“更早完成答案”须分别验收。
- **幂等与进度（有边界的实现）**：同一会话在进程内去重记录保留期间，重放不会重复记日志或增加已答题数；应用回合标识与可见历史指纹用于识别请求，不仅比较当前文本。缓存有界，不承诺跨重启或任意久远重放的去重；SQLite 笔记写入另有事务与会话/回合去重。
- **学习记忆（需明确开启）**：默认不读取或记录学习笔记，`/memory on` 后才按会话保存到 SQLite；数据库持久保存不等于任务进度持久恢复或跨会话识别同一用户。无可见历史且无可用状态时，不伪装可恢复。

## 7. 长 Prompt 与规则顺序的对照方法

不能看到 C/D 比其他分支弱，就认定长 Prompt 发生了“稀释”。按以下顺序排查：

1. 先检查输入是否同等明确、出题阶段是否返回完整可用题目、历史及状态是否实际进入模型，以及评分标准是否一致。
2. 检查规则冲突，例如默认三题是否被理解为提前三连调用、画像补问是否和练习同时出现、旧 mastery 是否重复触发升档。
3. 保存所涉及角色的基线完整 Prompt。对照版本只调整相关规则的位置，不同时精简正文、换模型、改编排或补充状态。
4. 固定模型部署与版本、采样设置、输入、角色及检索输出夹具、初始历史和状态；对同一组 C/D 用例重复运行基线与对照版本，检查其他分支是否退化。
5. 分别报告结构合规、主意图正确、程序编排正确、等待与停止正确、计划可执行等结果，保留所有失败轨迹与样本数。仅在观察到稳定差异时报告“本组条件下的位置调整效果”，不推广为通用因果结论。
