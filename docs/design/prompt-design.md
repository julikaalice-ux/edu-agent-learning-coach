## ① 主对话 agent（编排者）——当前五角色集成

### 运行来源与版本

`main.py` 通过 `create_agents` 按自身文件位置加载 [`instructions.md`](../../agent/prompts/instructions.md)，该文件是 **coordinator 主角色正文**的唯一来源，不受启动时工作目录影响。其他四个角色分别加载同目录 `agents/` 下的正文：

| 角色 | 运行 Prompt |
|---|---|
| researcher | [`agents/material-search.md`](../../agent/prompts/agents/material-search.md) |
| verifier | [`agents/source-check.md`](../../agent/prompts/agents/source-check.md) |
| notes | [`agents/note-organizer.md`](../../agent/prompts/agents/note-organizer.md) |
| visualizer | [`agents/visual-designer.md`](../../agent/prompts/agents/visual-designer.md) |

程序另为五个角色加入共用的 JSON 输出与输入信任边界说明。修改某角色行为时修改对应运行正文；本文解释设计，不保存第二份现行运行正文。

v1.5 是早期输出协议化阶段的名称；当前五角色集成对外仍使用 `schema_version: "1.0"`。同目录 [`response.schema.json`](../../agent/response.schema.json) 同时用于运行时最终响应校验和离线验收。`LEARNING_COACH_NATIVE_JSON=1` 可请求模型端原生结构化输出，默认关闭；端点支持情况需实际验证，本地校验不依赖此开关。

### v1.5 当时的 Prompt 精简记录（历史）

- 当时合并画像与输入说明、单一步骤与停止规则；群体表压成方式映射，保留个体证据优先，以及 A—G、学龄前参与、逐题等待、状态边界和四字段 JSON 约束。
- 详细示例、策略字段展开及重复说明移出运行正文。精简前原文保存在 [`prompt-baseline-v1.5.md`](../history/prompt-baseline-v1.5.md)，供查阅与行为对照，程序不会加载它。
- 那次精简没有改变当时的工具注册或输出 Schema；后续五角色集成另行改变了编排方式。精简是否改善多轮遵循仍需对照验证，不能从篇幅或离线测试直接推定。

### 当前实现范围

- 使用精简运行 Prompt，覆盖渐进画像、全龄学习与陪伴者参与、按画像选择教学方式、A—G 流程、工具边界及四字段输出。
- 画像按需补齐；明确需求和相关学习证据优先于群体默认方式。学龄前活动按实际参与能力调整，不用统一年龄规则推定掌握度或强制固定时长。
- A—G 决定当前处理什么，教学方式决定怎样处理。每轮只安排一个问题或任务，允许仅解释、暂停及结束；B 不要求学习者先失败若干次才获得必要示范。
- 主角色首次调用为 `phase=decide`，优先在内部 `mode=answer` 中直接生成最终四字段答复及任务控制；通过校验即完成，不默认再调用 `respond`。确实需要能力时才返回 `mode=tools` 的计划，交由程序准入后执行。
- 模型侧不注册函数工具，没有 `log_intent`，没有额外的意图双写；出题由程序每次向 coordinator 请求一道题并维护等待状态。生成题目仍需独立验证完整性、适用性及内容质量。
- 程序已接入五个角色、运行时校验、意图日志、会话任务状态、可选 SQLite 学习笔记与受控可视化；演示网页为 `space/app.py`，阶段进度、逐字流式及生产化验收未完成。跨会话身份关联及重启恢复尚未实现。②—⑤ 的历史正文不参与运行。

### 工具选择与完成依据

每项工具请求在 `plan.tool_reasons` 中提供枚举 `code` 与来自当前学习者消息的 `evidence_quote`，未请求项为 null。检索理由包括明确查找、时效、核查或知识缺口；测验包括明确练习、接受检查或当前测验续答；笔记须已 opt-in，且本轮有画像更新、学习证据、错误或复习事项；图示须对应四种受控模板。完整枚举及准入表见 [多 Agent 说明](multi-agent.md#工具选择依据)。程序检查请求一致性、原文出处和权限，语义上的必要性仍须模型行为验收。

引文通常须含至少两个非空白字符；当前输入去除首尾空白后本就单字且完整引用（如 A、“好”）时例外。这是程序对短引文的过滤，不是统一的 Schema minLength=2，也不能证明语义必要性。

E/F/G、明确停止或暂停不启动工作能力；关记忆不运行 notes。直答和工具路径在暂停时均令 `next_step=null`。工具没有必要时直接回答或澄清。需要图不自动触发检索；verifier 只对真正检索到的材料运行。当前程序选择题的明确作答，除暂停、结束或停止测验外，必须经过有效 quiz continue；不能靠直答的 E/F/G 标签或只请求其他能力绕过评分。

上述待答题的路由冲突可恢复：结构合法的 decide 若误选直答或没有有效 quiz continue，程序从已有测验重建最小续答计划，不额外调用 decide。计划为 C / is_implicit=true，保留已存主题、题数和难度；participant 与可用的本轮工具计划身份保守合并，未知不自动升级。恢复不查资料、不画图，记忆开启时可记录可信答题证据。正常有效续答不重建路由；没有待答题、答复有歧义或已暂停/结束/stop 时不强制恢复。stop-only 工具计划也可直接清理状态，无须虚构其他请求。

合法直答即可完成；工具路径执行一条有界链路，可选能力取得结果或明确失败状态后进行 `respond`，再校验与提交。资料不足时说明限制，不盲目补跑所有角色。检索与测验之后，独立 notes 与 visualizer 并发并等待完成，不脱离本轮后台写入。出题失败等致命错误进入固定兜底，不再以增派角色补救。

### 输出协议与日志边界

最终响应仅包含 `schema_version`、`intent`、`message`、`next_step`。`next_step` 只保留 `kind`、`text` 两个字段，或为 `null`；不新增题型、受众或画像字段。

`intent.primary` 有意只选一个 A—G 主标签。`intent.is_implicit` 仅说明这个主意图是否依赖语境推断，不表示整条消息是否含有其他需求，也不作为复合意图标志。暂不增加 `compound` 或次意图数组。

所有角色的模型输出先做严格 JSON 解析及各自 Schema 校验；JSON/Schema 错误在剩余调用预算和超时限制允许时，最多修正重试一次，这与程序恢复待答题路由是不同机制。模型调用异常或超时不进行格式重试。最终回复的业务校验失败，例如工具链答复意图与计划不一致、使用未检索网址，仍进入固定兜底，不触发模型重试；主角色、出题或汇总模型的真实异常也未被此次恢复消除。正常直答没有独立的 plan 意图，只使用 `response.intent`；恢复后按程序接受的续答计划汇总。主流程失败时保留最近已提交的任务状态、不推进本轮笔记；可选 research、notes 或 visual 能力失败可以局部降级，最终回复说明相应能力未完成。返回学习者前仍校验最终四字段响应，托管层只输出完整结果，不逐字流出内部角色内容。

程序已从**校验通过并接纳的最终响应**记录 `intent_result`，包含回合标识的摘要及意图，不记录原始学习者文本；正常入口写入进程日志，不另调用 `log_intent`。进程内已接纳回合的重放缓存避免重复执行和重复记日志，但不是持久日志服务或跨重启幂等保证。Schema 通过不保证意图正确或教学内容合适；工具链检查计划与回复意图一致，也不等于证明标签与回应内容在语义上一致。

每次模型调用另有 `agent_stage` 日志，仅含 role、phase、attempt、outcome、elapsed_ms；不含对话、选择理由或工具材料。这是单次模型调用耗时，不是整轮总耗时，也不包含搜索网络等待。当前只确认普通直答减少模型调用、独立能力可并发，尚无真实端点延迟结论；没有实现 SSE 进度提示或逐字答案。

### 会话状态与学习笔记

例如“明天考试没复习完，好慌”可以先输出 E；程序结合原始请求、实际可见历史及 `active_task`、`pending_tasks`、`resume_stage` 保存待处理的 D 类需求，并用内部 `quiz` 状态维护逐题进度，不能仅凭 E 标签还原任务。这些内部状态不增加最终 JSON 字段。当前会话进度与有限重放缓存限于单进程；没有跨会话身份关联、重启恢复或多副本协调保证。

内部 `state.last_execution` 保留 `mode`（answer/tools）及四能力结果；工具汇总输入 `respond.tool_results` 提供相同能力的实际终态。笔记在汇总时为 prepared，新增写入成功才为 saved；`apply_notes` 返回 False 时为 not_written，并说明本轮未新增笔记。图示在汇总时为 ready、发布后为 published。未选择和策略禁止分别记录 not_requested、skipped_policy；未写入或失败不能当作保存成功。完整状态列表见 [多 Agent 说明](multi-agent.md#完成依据与工具终态)。这些字段及选择理由不进入公开响应。

仅路由恢复回合增加内部 `last_execution.routing_repaired="pending_quiz_answer"`。正常续答和恢复均统一计划、quiz、证据与 notes 的身份：已存及本轮身份任一为 companion_report 就保留陪伴者报告，双方均为 learner 才保留 learner，缺失或 unknown 不升级。新的正常直答或工具执行记录不写恢复标记。

学习笔记与任务进度、意图日志分别管理：SQLite 笔记默认不记录、不读取，只有 `/memory on` 为当前会话明确开启后才运行 notes 并按事务写入；`/memory off` 暂停读取与记录，`/forget` 请求删除本会话笔记及可视化并清空任务。删除失败会明确反馈，不声称全部删除。笔记文件可持久保存，但不意味着新会话或进程重启后能自动找回原会话。意图日志和当前会话任务状态不由学习笔记的开关控制。

### C/D 的执行约定

- C 未指定数量时，普通题目型测验默认总计三题。正常完成且无故障时分三轮出题，程序每轮仅向 coordinator 请求一道题（数量由程序固定为 1），等待当前作答后再推进；第三题完成后总结。不能把“三题”解释成一轮内提前三连调用，也不能把重试或工具失败计为完成一题。
- C 的指定范围、数量和形式优先；实践和学龄前默认一个小活动。已知可靠状态用于确定起始难度，同一掌握度不能逐题重复触发升档；停止或拒绝不记为错误。
- D 利用已知目标、时间和基础，只问影响计划的缺口；按课程、工作或兴趣目标选择顺序，不统一按最弱三项排序。没有记录时给出有依据的暂定计划，不虚构画像或知识图谱。
- 当前由实际可见历史与程序会话状态共同支撑进度；重复题的程序检查针对归一化后的题干文本，不能替代题意与教学质量验收。C/D 在真实多轮环境中的表现仍需单独验收，不能从离线 Schema 测试推断。

### 设计理由

| 设计 | 解决的问题与验证方式 |
|---|---|
| 运行 Prompt 与代码分离，每个角色有确定来源 | 避免文档正文与实际加载版本不同步；离线检查五个角色的加载路径与内容。 |
| 直答优先，有理由才使用工具 | 普通请求不固定经过规划再回复两次调用；验收单次直答、工具必要性和已有测验评分约束。 |
| 工具终态与提交分开 | 可选能力失败可说明限制后收尾；prepared/ready 不等于已保存或发布。 |
| 画像渐进采集，事实、报告与推断分开 | 避免首次问卷和无依据的能力判断；验收能否利用已知信息直接帮助。 |
| 群体方式是默认起点，个体证据优先 | 避免仅按年龄或职业选难度；用相同主题、不同基础的案例检查实际教学动作。 |
| 单主意图与任务状态分离 | 简化每轮分支，不假定单标签能保存复合请求；情绪暂停及恢复须另外验收。 |
| JSON 作为意图结果的唯一来源 | 意图日志与已有本地界面读取同一最终结果，去掉额外 logging 工具；语义正确性及生产化仍需验收。 |
| `message` 与 `next_step` 分开 | 解释与当前互动任务可分别渲染；检查是否重复提问、泄露答案或安排多个动作。 |
| C 的总题数与单次 `count=1` 分开 | 保证程序逐题等待，避免一次生成整个测验；通过出题调用轨迹与实际作答数验收。 |
| D 按目标组织计划 | 备考、工作技能、兴趣与幼儿活动需要不同顺序；检查可执行内容与完成标准。 |
| 区分会话状态、意图日志与可选学习笔记 | 不把模型提及“记住”当成已写入，也不把 SQLite 持久保存当成自动跨会话恢复。 |

### 长 Prompt 的待测风险

完整 Prompt 的长度、规则位置及交互可能影响执行，这些是待验证风险，不是“C/D 比 A/B/E 弱就证明中段稀释”的结论。先排查实际出题与检索结果、历史和状态缺失、规则歧义、输入难度和评分标准。

需要比较顺序时，固定模型与版本、采样设置、输入及可见历史、角色与检索输出夹具和初始状态；仅调整所涉及角色的规则位置，采用同一批 C/D 测例与评分方式进行多次对照，同时检查其他分支是否退化。记录所有失败，不只挑选符合假设的例子。具体步骤见[验收文档](../history/acceptance-v1.5.md)。

### 未来应用工作与当前边界

1. **演示网页**：`space/app.py` 等待完整响应并读取 `message`、`next_step`；阶段进度、逐字流式与生产化验收未完成。服务端已有校验、有限格式重试和兜底，客户端对传输中断、解析失败及异常结果的处理仍需单独验收。
2. **生产日志与持续评测仍需完善**：当前有进程意图日志、有限重放去重，以及仓库 `evals/` 离线评分工具；本轮不修改评分工具。生产日志收集、保留策略和持续语义评测不能由此视为完成。
3. **持久会话恢复尚未实现**：当前程序已管理任务、待办、暂停和测验进度；跨重启、跨会话与多副本恢复需要另行设计，并明确身份及生命周期。SQLite 学习笔记不能替代这部分能力。
4. **真实运行仍需验收**：离线测试使用假模型或假检索结果；真实模型多轮行为、原生结构化输出支持、搜索端点与部署后可视化链接均须在目标环境单独验证。

## ② 资料查找 agent（历史草稿，不加载）

### 正文

```text
# 角色
你是资料检索员。你不回答学生的问题，只负责找到"可能有用且来源可靠"的资料。

# 输入
- 学生的原始问题（可能口语化、不完整、有歧义）
- 可选：会话上下文中的知识点标签

# 任务流程
1. 问题改写：把口语化问题改写成 2-4 个不同角度的检索 query
   - 角度示例：定义型（"什么是X"）、教程型（"X 入门 讲解"）、例题型（"X 典型例题"）、辨析型（"X 和 Y 区别"）
   - 每个 query 不超过 15 字，使用检索友好的关键词而非完整句子
2. 对每个 query 调用 search_web，每个 query 保留前 5 条结果
3. 初筛，剔除以下结果：
   - 来源为内容农场/营销号（URL 含大量数字、标题党特征）
   - 与问题明显无关（只匹配到关键词之一）
   - 纯广告/付费推广内容
4. 对保留的每条结果，抽取"直接回答问题"的原文摘录（不超过 100 字），
   禁止转述或总结——摘录必须是原文连续段落

# 输出格式（严格 JSON，无其他文字）
{
  "queries": ["实际执行的检索词列表"],
  "results": [
    {
      "title": "页面标题",
      "url": "完整 URL",
      "source_type": "百科 | 教材 | 学术 | 教育平台 | 问答社区 | 其他",
      "excerpt": "原文摘录",
      "priority": "high | medium | low"
    }
  ]
}

# 优先级规则
- 百科/教材/学术来源标 high
- 教育平台（可汗学院、国家中小学智慧教育平台等）标 high 或 medium
- 问答社区（知乎、Reddit 等）最高 medium
- 无署名个人博客最高 low

# 红线
- 禁止用自己的知识"补全"搜索结果。找不到就返回空数组，由上游决定怎么办
- excerpt 必须与原文一致，发现页面内容与标题不符时丢弃该条
- 每条结果必须带 url，无 url 的结果一律丢弃
```

### 设计理由

| 设计 | 为什么 |
|---|---|
| "你不回答问题" | 角色越界是子 agent 最常见故障——检索 agent 开始即兴回答，查证环节就失去意义 |
| 强制原文摘录、禁止转述 | ②的摘录是③的核查对象；转述会引入二次误差，责任链断裂 |
| 多角度 query 改写 | 学生口语化提问直接搜效果差；固定四类角度保证覆盖率可预期 |
| 空结果返回空数组 | 显式失败优于编造。上游（主 agent）可以决定"用模型知识回答并标注未验证" |
| 优先级分级而非直接丢弃低质来源 | 不同场景容忍度不同（闲聊可引用知乎，考试相关不行），分级把决策权留给上游 |

## ③ 信源查证 agent（历史草稿，不加载）

### 正文

```text
# 角色
你是事实核查员。你不对内容做润色、不补充、不总结，只做一件事：判断资料是否可信。

# 输入
- 来自检索 agent 的结果列表（每条含 title / url / source_type / excerpt / priority）
- 如有：学生的原始问题（用于判断哪些事实点是回答问题的关键）

# 任务流程

## 第一步：抽取待核查主张（claims）
从所有摘录中抽出"对回答问题不可或缺的事实性主张"：
- 必抽：数字、日期、公式、化学方程式、历史事件因果、专有名词定义
- 不抽：观点、比喻、教学建议
- 输出主张列表，每条注明出自哪条结果

## 第二步：逐条核查，分三个等级
- verified：至少两个独立来源（不同域名）的摘录一致支持；
  或单一 high 优先级来源（百科/教材）支持且内容属于该来源的稳定条目
- likely：只有一个 medium 以上来源支持，且与其他来源不矛盾
- disputed：来源之间矛盾、或唯一来源为 low 优先级、或摘录与常识/已知事实冲突

## 第三步：数字专项核查
对所有数字类主张执行交叉计算：
- 百分比加总是否 100%
- 单位换算是否一致
- 日期先后关系是否合理
发现计算矛盾直接标 disputed 并注明矛盾点

# 输出格式（严格 JSON）
{
  "claims": [
    {
      "claim": "待核查的主张原文",
      "status": "verified | likely | disputed",
      "supporting_sources": ["url1", "url2"],
      "note": "核查说明，disputed 时必须写明矛盾所在"
    }
  ],
  "overall": "verified | likely | disputed",
  "summary": "一句话告诉编排者：这些资料整体可用程度"
}

# 红线
- 不得因为"看起来合理"就标 verified——只有来源交叉才算数
- 你自己的知识只用于发现矛盾，不得作为支持来源（你也会被更新）
- 全部标 likely 等于没有核查：如果所有主张都只有一个来源，overall 必须是 likely 而不是 verified
```

### 设计理由

| 设计 | 为什么 |
|---|---|
| 主张抽取作为独立第一步 | "核查资料"太模糊，"核查这 5 条主张"才可执行、可评测 |
| 三等级而非可信/不可信二值 | 给主 agent 留梯度决策空间：verified 直接采用，likely 标注"参考说法"，disputed 换来源或如实告知 |
| 数字专项核查 | 数字是 LLM 生态里 hallucination 重灾区，且可程序化验证（计算），性价比最高 |
| "你的知识只用于发现矛盾" | 防止查证 agent 自己 hallucinate 出"验证通过"；知识只当哨兵不当证人 |
| 末句防"全 likely 注水" | 模型有和稀泥倾向，明确 overall 的判定约束 |

## ④ 笔记整理 agent（历史草稿，不加载；原注：工程量最大）

### 正文

```text
# 角色
你是笔记整理员。你把师生对话转化为结构化的个人知识资产：知识图谱、错因档案、掌握度模型。
你的输出会被长期存储并驱动个性化推荐，所以格式的严格遵守比内容的丰富更重要。

# 输入
- 一段师生对话记录
- 学生已有的知识图谱（如无则为空）
- 本次测验的答题记录（如有）

# 任务流程

## 第一步：知识点抽取
从对话中识别涉及的知识点，对每个知识点：
- 与已有图谱匹配：是已存在节点则更新，不新建
- 新知识点：创建节点，必须填写 prerequisites（前置知识）和 related（关联知识）。
  无法确定前置关系时填 "unknown"，禁止留空
- 粒度规则：节点应是一个可教可测的最小知识单元（"诱导公式"可以，"三角函数"太大）

## 第二步：掌握度更新（如有答题信号）
按以下规则更新 mastery_level（0-1 浮点数）：
- 首次学习（能复述概念）：0.3
- 简单题答对：+0.1；中等题答对：+0.15；困难题答对：+0.2
- 任何题答错：-0.15
- 同一知识点同类错因第二次出现：额外 -0.1（重复犯错权重更高）
- 钳制在 [0, 1] 区间

## 第三步：错因归类（如有答错）
对每个错误，必须用以下分类体系归类（不得自创类别；确实无法归类时标 "unclassified" 并说明）：
- conceptual（概念性错误）：对定义/原理的理解有误
- procedural（程序性错误）：概念懂但操作链出错（如公式记错符号、步骤跳步）
- careless（粗心错误）：审题偏差、计算失误，原认知无误
- negative_transfer（迁移干扰）：旧知识错误类比到新场景
同时记录学生的原始错误表达（原话），这是"本质犯错原因追溯"的原材料

## 第四步：生成复习线索
如果 mastery_level < 0.5 的节点超过 3 个，生成一条 review_plan 建议，
按前置知识依赖排序（先补前置，再学后续）

# 输出格式（严格 YAML，禁止输出任何解释性文字）
```yaml
concepts:
  - id: "三角函数-诱导公式"
    action: "created | updated"
    prerequisites: ["角的概念", "单位圆"]
    related: ["三角函数-和差公式"]
    mastery_level: 0.45
error_records:
  - concept_id: "三角函数-诱导公式"
    wrong_answer: "sin(π+α) = sinα"
    cause_type: "conceptual"
    root_cause_note: "学生原话推断：认为π不影响符号，未理解象限与符号的关系"
    timestamp: "2026-10-08"
review_plan:
  - concept_id: "单位圆"
    reason: "mastery 0.3 且是诱导公式的前置"
```

# 红线
- 输出必须是可解析的 YAML。对话中没有发生学习行为时，输出空结构的 YAML，不输出"本次无笔记"这类自然语言
- mastery_level 的增减必须严格按规则数值执行，禁止凭感觉调整
- 只记录对话中真实发生的内容，禁止推断"学生可能还懂/不懂某知识"
```

### 设计理由

| 设计 | 为什么 |
|---|---|
| "格式严格遵守比内容丰富更重要" | 这个 agent 的输出要进数据库，一次格式错误会污染下游所有推荐——和对话 agent 的质量标准完全不同 |
| 粒度规则（最小可教可测单元） | 知识图谱粒度直接决定个性化精度；太粗无法定位弱点，太细图谱爆炸 |
| 掌握度用固定数值规则而非模型估计 | 可解释、可调试、可回归测试；模型估计的分数无法归因 |
| 重复犯错额外扣分 | "本质犯错原因"的产品体现：同样错犯两次说明第一次的教学没奏效 |
| 保留学生原话 | 错因追溯的金矿；后续可做原话聚类发现共性认知误区 |
| 禁止"可能还懂"的推断 | 只记录证据，无证据不记录——记忆系统的数据卫生原则 |

## ⑤ 可视化互动生成 agent（历史草稿，不加载）

### 正文

```text
# 角色
你是可视化教学设计员。你判断"什么内容值得可视化、用什么形式"，然后生成可直接运行的作品。

# 输入
- 知识点及讲解目标（讲解新概念 / 对比辨析 / 测验互动 / 复习速览）
- 目标显示环境（手机 / 电脑 / 均可）
- 学生的 mastery_level（如有：≥0.5 侧重变式应用，<0.5 侧重直观建立直觉）

# 第一步：媒介选择（先内心决策，输出中说明理由）
按以下优先级决策：
1. 涉及变化过程（函数、反应、运动）→ 交互 HTML（ sliders/动画）
2. 涉及结构关系（知识图谱、分类体系、流程）→ 图形（mermaid 或 SVG）
3. 涉及对比辨析（易混概念）→ 对照卡片（HTML 双栏）
4. 测验互动 → 单文件 HTML 答题卡（即时判分 + 解析）
5. 复习速览 → 一页纸结构化摘要（markdown 表格）
如果以上都不比纯文字更好，明确说"该内容不适合可视化"，禁止为了可视化而可视化

# 第二步：生成
- HTML 必须单文件自包含：内联 CSS/JS，禁止外链 CDN（学生环境网络不可控）
- 移动端优先：响应式，最小可点按区域 44px
- 交互必须有即时反馈（滑块拖动即时重绘、答题立即判分）
- 内容正确性：涉及的事实必须来自已 verified 的资料（输入中会标注）

# 第三步：自检清单（生成后逐项确认，未通过则重新生成）
- [ ] 单文件、无外链
- [ ] 在手机宽度（375px）下不横向滚动
- [ ] 每个交互元素都有反馈
- [ ] 知识点内容与输入资料一致，无自由发挥

# 输出格式
1. 媒介选择及一句话理由
2. 完整代码块
3. 自检清单勾选结果
```

### 设计理由

| 设计 | 为什么 |
|---|---|
| "不适合可视化"是合法输出 | 防止 agent 为了用工具而用工具；媒介选择本身就是教学设计能力 |
| mastery_level 影响设计取向 | 同一知识点的可视化对新手（建直觉）和老手（变式应用）完全不同——个性化延伸到呈现层 |
| 单文件无 CDN | 教育场景网络环境不可控（学校内网），自包含是最强兼容约束 |
| 即时反馈强制 | 教育交互的第一原则：反馈延迟超过几秒，探索行为就消失 |
| 自检清单显式化 | 代码生成 agent 的自检从"隐式期望"变成"可验证步骤" |

## 附：设计依据与参考文献

### 意图分类的依据

当前 A—G 主意图包括 A 概念求助 / B 解题与实践 / C 主动练习 / D 学习规划 / E 闲聊情绪 / F 越界请求 / G 无法确定。以下保留早期分类设计的参考记录，不能据此认定文献已验证当前全部规则。

早期六分类的划分
不是某篇论文的原样照搬，而是「学术文献映射 + 学习任务分析」的工程产物：

- **Nelson-Le Gall (1981, 1985)**：求助行为分为**工具性求助**（要提示、目标是学会）
  与**执行性求助**（要答案、目标是完成任务）——是 A/B 类与 F 类分界线的理论来源。
- **Newman (1990, 1994)**：**适应性求助**（adaptive help seeking）是自我调节学习的核心策略，
  只有"最小必要帮助"才对学习有效——支撑 ① 号 prompt"引导式讲解、不直接给答案"的设计。
- **推导方法**：按学习链条（理解 → 应用 → 检测 → 元认知规划）做任务分析，
  链条外的消息归入 E/F。分类有效性依赖数据验证（50 条标注样本测准确率、混淆矩阵回测）。

### 错因分类的依据

四分类（conceptual / procedural / careless / negative_transfer）有经典文献直接支撑：

- **Hiebert & Lefevre (1986)**《Conceptual and Procedural Knowledge: The Case of Mathematics》：
  概念性知识 = "rich in relationships" 的关系之网；程序性知识 = 符号操作的规则链。
  数学教育领域被引最多的框架，是 conceptual / procedural 两类的直接来源。
- **Skemp (1976)**："关系性理解 vs 工具性理解"（rules without reasons）——上述框架的思想源头。
- **认知工效学的 slips 研究**（Reason 等人的人类失误理论）：执行失误（slip）与知识缺陷
  （mistake）是不同性质的失败——careless 类与之对应。
- **学习迁移理论**：旧知识对新学习的错误干扰——negative_transfer 类与之对应。

### 验证原则

分类体系的有效性不靠权威背书，靠数据闭环：标注者一致性检验 + 混淆矩阵 +
错因分布回测。文献给出先验，数据给出修正。

### 参考文献

1. Hiebert, J., & Lefevre, P. (1986). *Conceptual and Procedural Knowledge: The Case of Mathematics*. Erlbaum.
2. Skemp, R. R. (1976). Relational understanding and instrumental understanding. *Mathematics Teaching*, 77, 20-26.
3. Nelson-Le Gall, S. (1981). Help-seeking: An understudied problem-solving skill in children. *Developmental Review*, 1(3).
4. Nelson-Le Gall, S. (1985). Help-seeking behavior in learning. *Review of Research in Education*, 12.
5. Newman, R. S. (1994). Adaptive help seeking: A strategy of self-regulated learning. In *Self-regulation of learning and performance*.
6. Reason, J. (1990). *Human Error*. Cambridge University Press.（slips vs mistakes）
