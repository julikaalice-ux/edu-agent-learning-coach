# Prompt 家规 v1.0

> 本项目所有 prompt 文件（编排者、专家、工具描述）必须遵守的设计规范。
> 新增 agent 或修改 prompt 前，先过一遍这八条。每条附"怎么检查"——家规本身也要可判定。

---

## ① 可判定性原则

每条规则必须能回答：**"它在防哪种失败？"** 答不出来的规则是许愿，删掉。

- 写法：先想这个 agent 会怎么坏，再写防它的规则
- 检查：逐条问"这条防什么"；答不上来就删

## ② 三层输出规范

- **硬规范**：可二元检查的行为与红线（防幻觉、拒绝两步走、结尾推进）
- **弹性区间**：给范围不给点值（"1-3 句"而非"150 字"）
- **完全自主**：措辞、类比、具体说法——这是模型的发挥空间，写出来只会限制上限

检查：每条规范放进三层之一；放不进去的层级的规则重写。

## ③ 风格不焊死

emoji、语气词、句式等风格细节给原则不给禁令。禁令只用于可枚举的反例
（如"禁止空洞鼓励：'你不笨''加油你可以的'"）。

## ④ 工具缺失要显式声明

没有的能力明确标注版本和限制（"当前限制（v3a）：无联网检索"），并在输出层降级
（标 needs_fetch / 最高 likely）。**宁可显式示弱，不可静默装强。**
工具失败不得描述为成功。

## ⑤ 输出格式给死

下游是程序的输出，格式严格遵守比内容丰富更重要：严格 JSON/YAML、
禁止解释性文字、schema 写明。格式错误会污染整个下游链路。

## ⑥ 版本痕迹要留

临时的妥协（模拟题库、无联网、无记忆写入）写成显式的"当前限制（版本号）"段落。
升级时知道拆哪块；面试时知道怎么讲演进。

## ⑦ 单轮单目标

每次交互只有一个目标、最多一个下一步。提问后等待，不替学习者作答，
不模拟用户行为。agent 之间的调用同样：一次 consult 只干一件事。

## ⑧ 证据与推断分离

明确陈述 > 可观察表现 > 暂定推断 > 临时假设。
推断不存为事实；无评分策略不生成精确分数；
模型自身知识只用于发现矛盾，不得作为支持来源。

---

## 附：新增 prompt 文件的验收清单

- [ ] 硬规则每条都能说出防的失效模式
- [ ] 有"当前限制"段落（没有也要写"无"）
- [ ] 输出格式是严格 schema，附示例
- [ ] 遵守"不编造"红线：无工具支撑的事实性输出必有降级标注
- [ ] 篇幅受控：超过约 100 行先问"是不是该拆 agent 了"
